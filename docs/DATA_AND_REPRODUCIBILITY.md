# Data contracts and reproducibility

## Observation files

`TW1_DATA_DIR` points to a parent containing `2021/` and `2023/`. The authoritative per-workflow filenames, processing variants, time conventions, and selected intervals are in [`tw1/cases.json`](../tw1/cases.json). Its 59 presets are workflow selections, not 59 independent scientific events. `2021/outdated/` and `2021/[phase]/` represent distinct processing products and are never substituted automatically.

Station text products are whitespace-delimited numerical arrays with time in column 0. The common frequency reader uses column 1; phase workflows use the phase column specified in their implementation. `time_formats` declares `utc_code` (`YYYYDDDHHMMSS`, optionally fractional seconds) or `sod` (UTC seconds of day) for each filename. `frequency_signs` records polarity corrections. Windows exclude both endpoints and must remain within one UTC day.

PLL conversion reads `<observation>/<station>/<channel>/Time_Frequency_Phase.mat`, variable `Fre_Pha_data`, and writes the array as text. Supply `--output` when running `read_PLL_data.py` to keep new conversion products separate from the original observations.

## Derived inputs and outputs

Paths below are relative to the sibling `RESULT/` directory, not to the shell working directory. These input workbooks and tables are not bundled or automatically generated by case selection.

| Input | Consumers and required content |
| --- | --- |
| `wavelet_coherence.xlsx` | Both coherence statistics workflows; sheets `distribution` and `coherency`, including dates, solar offsets, station/baseline geometry, periods, and propagation measurements used by each script. |
| `multiple_baseline.xlsx` | `analyse_multiple_baseline.py`: sheets `coherency` and `station_info`; `plot_density_fluctuation.py`: sheet `density_fluc`. Preserve the source column names and event ordering used by the scripts. |
| `base_line_spikes_multiple/lagvelocity_baseline_neaten.txt` | Spike multibaseline fitting; whitespace table with `year`, `month`, `day`, `second`, `stat1`, `stat2`, `coef`, `lag`, `lag_err`, `vel`, `vel_err`, `lat_proj`, `r_proj`, `bl_t`, and `bl_r`. |
| `base_line_multiple/cases.xlsx` | Optional MATLAB wavevector calculation; columns for date, time, three position coordinates, scale, phase speed, and direction. |
| `multiple_baseline_rmse/zoom_in/summary.csv` | Input to `plot_2d_propagation_composite.py`, generated by the zoom-in multibaseline analysis. |

New multibaseline outputs use `multiple_baseline_rmse/zoom_in`, `zoom_out`, or `spikes`. Each contains fit summary tables and diagnostic figures. The composite script retains its historical output location `../PAPER/Figures/2Dpropagation(6).png`; create that directory before running it, and note that running it replaces that figure.

## Scientific assumptions and missing components

- Wavelet lag signs depend on station ordering and phase conventions. High coherence alone does not establish a unique wave mode or remove phase wrapping and projection ambiguities.
- The multibaseline fit uses `v_i = V / cos(theta - phi_i)`, with signed baseline velocities and a common plane-wave structure. Read [`MULTIBASELINE_METHOD.md`](../MULTIBASELINE_METHOD.md) for constraints, residual interpretation, conditional errors, and the one residual degree of freedom for three baselines and two fitted parameters.
- Density estimates retain the original line-of-sight geometry, model density, sample selection, and integration assumptions. Numerical integration warnings may still occur; passing regression checks does not establish scientific accuracy of those assumptions.
- `python_utils_JSHEPT.py` and the large `de430.bsp` ephemeris are external. The manuscript's separate MHD solver and an automated classical-correlation-to-publication pipeline are not supplied by this snapshot.
- The final paper points to [lag-analysis code/data](https://doi.org/10.5281/zenodo.21369407) and [simulation data](https://doi.org/10.5281/zenodo.19362826). Their current contents were not independently retrieved during this release preparation, so no exact catalog-to-archive mapping is asserted.
- The four README images are rendered from the final published article. They must not be interpreted as output from a fresh execution of the current local code.

## Validation scope

Run `python -m unittest test_multibaseline_fit -v` for the synthetic fitting tests. With the complete local observations, use `python run_analysis.py --check` and `python -m unittest discover -s . -p 'test_*.py' -v` for the existing full regression suite. A file-existence check is not a check of data quality or a reproduction of the paper.

The retained [Chinese workflow notes](LOCAL_WORKFLOW_ZH.md) document an earlier local restructuring and its historical validation. For the checks performed for this publication release, see [release validation](RELEASE_VALIDATION.md).
